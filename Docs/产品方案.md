# miniEasyConnect 产品方案

日期：2026-10-25  
方案层级：主产品方案  
状态：产品范围草案，供后续技术方案承接  
项目名：miniEasyConnect

## 1. 方案定义

面向个人使用的轻量 macOS VPN 客户端。使用 SwiftUI 提供简单的原生界面，复用 ZJU Connect 核心，以 TUN 模式访问授权内网，仅支持 Apple 芯片的 Mac。

用户输入 VPN 地址、账号和密码并提交后，先保存连接记录，再尝试连接。连接失败、验证未通过或用户取消连接都保留记录，以后点击记录即可重试，关闭窗口后继续在后台运行。

## 2. 核心问题与目的

对于只需要连接内网的使用场景，客户端应减少操作步骤和后台资源开销。

核心目的：保留 EasyConnect“连接后即可直接使用内网”的操作体验，降低后台资源占用。

连接成功后，浏览器、终端和其他应用应直接按 VPN 路由访问授权内网，不要求用户逐个配置代理。资源优化以保留这一体验为前提。

优先顺序：

1. 授权内网能实际访问。
2. 保存记录后可以一键连接，连接能够在后台维持。
3. 断开或退出后，电脑网络恢复正常。
4. 在以上功能成立的基础上，尽量降低内存和 CPU 占用。

## 3. 使用对象与核心场景

使用对象是需要通过 EasyConnect 协议访问内网的 Apple 芯片 Mac 用户。连接能力以所集成 ZJU Connect 版本及目标服务端配置的兼容性为准，沿用已有服务端配置。

| 场景 | 用户希望得到的结果 |
| --- | --- |
| 首次使用 | 输入 VPN 地址、账号和密码后即可连接 |
| 日常使用 | 点击已保存的连接记录即可访问授权内网 |
| 工作期间 | 关闭窗口后仍保持连接，正常使用内网应用 |
| 密码或地址变更 | 修改原有记录后重新连接 |
| 工作结束 | 主动断开或退出，恢复正常网络状态 |

## 4. 产品解决思路

| 解决方法 | 对核心目的的作用 | 对应能力 |
| --- | --- | --- |
| 复用现有 VPN 核心 | 沿用已有协议能力，优先实现内网连接 | 连接、断开、内网访问 |
| 保存可重复使用的连接记录 | 消除日常重复填写信息的操作 | 新建、保存、选择、修改和删除记录 |
| 将连接保持在后台 | 连接建立后不占用用户注意力 | 后台运行、状态提示、恢复连接、退出清理 |
| 使用简洁的原生界面 | 降低操作和界面资源开销 | 连接入口、记录列表、必要的状态与错误提示 |

SwiftUI、ZJU Connect 和 TUN 模式是已确定的实现约束。具体集成方式、后台进程和系统授权方式在技术方案中确定。

## 5. 核心业务主流程

### 首次连接

1. 没有连接记录时，点击顶部大图标或记录区域的“+”新建连接。
2. 输入 VPN 地址、账号和密码。
3. 校验并保存连接记录；保存失败时留在输入界面提示原因，不发起连接。
4. 发起连接并显示实际状态；系统需要网络操作授权时，在系统提示中完成授权。
5. 关闭窗口，连接继续在后台运行。

连接失败时提示可理解的原因，已保存的地址、账号和密码继续保留，允许修改后重试。保存记录不代表服务端已通过认证。

### 后续连接

打开应用，点击顶部大图标，使用最近一次发起连接的记录直接连接；重启应用后仍记住该记录。也可以点击任意已保存记录的“连接”。首次升级尚无最近使用信息、或最近记录已删除时，使用列表第一条记录；没有记录时打开新建连接。记录区域的“+”始终用于新建连接。密码失效时允许修改并保存新密码，再重新连接。

### 连接期间与结束

用户通过主窗口或菜单栏查看状态、断开连接。关闭窗口只收起界面；选择“退出”时先结束连接，再退出应用。断开后恢复本次连接修改的网络设置。

短暂断网或电脑唤醒后，在网络恢复时尝试恢复连接；需要重新输入密码或服务端要求的验证信息时，提示用户处理。用户主动断开后保持断开状态。

## 6. 功能与能力骨架

### 6.1 连接记录

保存 VPN 地址、账号和密码，支持新建、选择、修改和删除。记录以地址和账号区分，同一时间维持一个连接。

删除记录前弹出二次确认，默认选择取消；确认后删除该记录及保存的密码，取消时保留原记录。

每条记录可填写备注，方便区分用途。列表与菜单栏优先显示备注，未填写时显示地址；列表仍保留地址、端口和账号。备注不参与连接认证和记录去重。

已保存记录可以单独修改备注，保存后立即生效，当前连接继续保持。

新建相同地址和账号时更新已有记录；修改记录时如果与另一条重复，则提示使用已有记录。

地址和账号保存在本机，密码保存在 macOS 钥匙串中。记录管理与密码保存共同实现后续一键连接。

密码默认隐藏，输入框右侧的眼睛按钮可以切换显示和隐藏。各输入框保留字段标签，不显示占位文字。

记录在提交时保存，不以连接结果为条件。保存失败时不开始连接；新记录和新密码已保存、但旧凭据清理失败时，保留实际保存结果并明确提示清理问题。

### 6.2 内网连接

使用保存的记录建立连接，让浏览器和日常工作应用直接访问授权内网。所需的内网访问路径和域名解析由应用处理，用户只操作连接与断开。

成功登录是连接过程的一部分，不能仅凭核心进程启动就显示“已连接”。产品交付需要以内网实际可访问为依据。

### 6.3 后台运行与连接状态

主界面展示连接状态、操作按钮和连接记录列表。

断开时显示“正在断开”，不额外展示网络恢复说明。

关闭主窗口后继续维持连接，通过轻量菜单栏入口重新打开窗口或断开连接。界面提供未连接、连接中、已连接、恢复中、连接失败等必要状态。

出现问题时显示简短原因和下一步操作，不建设独立日志页面或权限管理页面。系统要求的网络操作授权仍需保留。

### 6.4 断开与网络恢复

主动断开、切换连接和退出应用时，结束当前连接并恢复本次修改的网络设置。异常结束后再次启动时，需要能够处理上次连接留下的网络状态，避免影响后续上网。

## 7. 资源目标与交付判断

以内网访问和后台稳定性为优先，争取将稳定连接、窗口关闭时的整体内存控制在 **100 MB 以内**。这是优化目标，不是已经验证的结果，也不作为阻止基础功能交付的硬性门槛。

统计应包含界面、VPN 核心和本应用专用的辅助进程，并在报告中明确测量口径。连接建立时的峰值与稳定后台占用分别记录；空闲后台尽量避免持续 CPU 消耗。

产品完成与否主要看以下结果：

- 首次输入信息后能够访问授权的内网服务。
- 重新启动应用后，保存的记录可用于一键连接。
- 连接失败、验证未通过或取消后，重新启动仍能读取已提交保存的记录。
- 关闭窗口后连接继续保持，连接中断时有准确状态和恢复路径。
- 主动断开或退出后，内外网访问符合断开前的正常网络配置。
- 提供同一台电脑上的实际资源测量结果，覆盖全部相关进程。

## 8. 依据与需在技术方案中核实的事项

ZJU Connect 的能力参考公开源码及说明：

- 上游仓库：[Mythologyli/zju-connect](https://github.com/Mythologyli/zju-connect)。
- 本次参考提交：`c19eb4ed34b9cf6e8e8ea3315fe9973c8411eb63`。
- 上游 README 说明 TUN 模式需要管理员权限，并给出了 EasyConnect 协议下的路由和 DNS 配置建议。

后续集成版本需在授权测试环境中验证连接能力。

后续技术方案需核实两项影响日常使用的事项：

1. **网络与状态一致性**：确认路由和域名解析正常，并确保界面状态与内网实际可用情况一致。
2. **服务端的额外验证要求**：基本流程按地址、账号和密码设计；如果服务端要求验证码，需提供最小的补充输入流程，保存密码不能代替服务端要求的验证。

后续技术方案以本文范围为输入，明确核心集成、连接记录、系统授权、后台维持及网络恢复的实现方式。

项目文档面向公开 GitHub 仓库。文档、示例配置、截图及验证报告统一使用虚构或脱敏内容，不包含真实组织信息、VPN 地址、内网域名和 IP、账号、密码、会话凭据、本机用户路径或内部测试记录。

实际连接记录与凭据保存在用户本机的应用数据位置和系统钥匙串中，不写入项目目录或版本库。
