## 已执行的验证

| 范围 | 方式与结果 | 证据的边界 |
| --- | --- | --- |
| Swift 工程 | 共享模型、App、Helper 类型检查和完整链接通过；重新构建后打开应用 | 不代表 VPN 服务端兼容性已通过 |

| 核心通信 | 实际辅助服务启动内置核心，收到证书挑战与失败事件；取消后核心进程退出 | 已验证进程通信，不等于成功登录 VPN |
| 证书 | 临时本地 TLS 服务：无信任拦截、精确指纹允许、错误指纹拒绝；App 可显示证书确认并取消 | 本地测试证书，未包含任何真实组织资料 |
| 非 VPN 地址 | 本地普通 HTML 服务触发了上游正则越界；修复后返回 unsupportedServer 并正常退出 | 不冒充真实服务端登录成功 |
| 记录与钥匙串 | 临时程序调用真实存储实现，验证地址规范化、密码原样保存、读取、更新、旧凭据清理和删除，全部通过 | UI 保存与一键重连还需结合成功连接场景验证 |
| 子进程退出竞态 | 临时程序复用真实 Supervisor，完成 103 项管道退出验证；含无换行最后事件、提前 EOF 和子孙持有输出 | 验证程序使用替代恢复层，没有修改真实系统 DNS |
| 取消与资源释放 | 静默 TLS 握手取消在一秒内结束；部分握手失败关闭已有连接；限制传输重试次数 | 仍需真实长时间连接观察 |
| 缓存上限 | 临时运行验证超过 4096 项时真实 DNS 映射淘汰旧项，保留新项 | 不代表完整流量压力验证 |

临时程序与测试配置不进入公开仓库。集成模拟核心仅用于验证界面、进程与系统配置恢复，不作为实际 VPN 认证或隧道传输成功的证据；验证后恢复正式核心。

## 审查修复

已通过主代理与子代理交叉检查并修复：

- 握手部分失败泄漏已有连接，读写重连后没有实际重试。
- 传输协程异常退出不能统一释放，以及 DNS I/O 不能及时响应取消。
- DNS 授权域名映射缺失、动态路由和缓存可能持续增长。
- TUN 变化被当作物理出口变化，引发反复重连的风险。
- 核心最后失败事件与进程退出竞态，可能将认证错误误判为可重试退出。
- DNS 整字典比较误判冲突，以及网络配置锁无限等待阻塞停止流程。
- launchd 相对启动路径导致找不到正确的核心文件。
- 首次服务注册待批准时误报普通失败；服务未启动时退出可能被取消。
- 非 VPN 网页缺少必需登录字段导致越界崩溃。

## 资源测量进度

目前只取得未连接、主窗口打开的初步结果：10 秒、6 次采样，App 与辅助服务总 RSS 平均约 122.8 MB，采样 CPU 为 0.0%。没有运行 VPN 核心，不能用这个结果代表已连接总占用。

同一阶段另用系统工具观察到 App 单进程 physical footprint 约 40 MB。physical footprint 与 RSS 是不同口径，不能直接混加或用一个替换另一个来宣称达到目标。

真实连接下的三进程总量、窗口关闭、持续传输、长期增长和同条件 EasyConnect 对比均待完成。当前不宣称已达到整体 100 MB 目标。
