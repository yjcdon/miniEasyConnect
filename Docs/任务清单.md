# miniEasyConnect 任务清单

日期：2026-10-25  
依据：[产品方案](产品方案.md) · [技术方案](技术方案.md)  
当前状态：功能实现已展开，构建与部分实机验证通过；完整证据见[验收记录](验收记录.md)。勾选表示该任务的完成条件已得到验证，其余不因代码存在而提前勾选。

## 执行原则

目标是保留“连接后直接使用内网”的体验，降低整体资源占用。按阶段推进，每项任务完成后记录验证结果，再勾选完成；编译成功不等于连接功能验收通过。

先打通真实连接及网络恢复，再完善记录、后台重连和资源优化。首次真实网络变更前，必须具备恢复机制。所有公开交付物只使用虚构或脱敏信息。

功能对应：F-01 连接记录、F-02 内网连接、F-03 后台运行与连接状态、F-04 断开与网络恢复。

## 实施顺序与完成记录

建议按阶段顺序执行。阶段二中先完成 T06 恢复机制，再进行 T07、T08 的真实网络变更；T10 验收通过后进入日常功能完善。签名条件、最低系统版本和核心适配可行性在 T01—T05 尽早核实，避免到打包时才发现阻塞。

每项任务完成时，在该任务下补充简短的完成记录：实现结果、验证方式及结果、仍存在的问题、对应提交（若已提交）。涉及范围变化时同步更新产品方案或技术方案，不保留互相矛盾的设计。

验证沿用编译、相关现有测试和人工实机检查，不要求新增测试类。没有执行过的验证标为“未验证”，不勾选依赖该结果的任务。
